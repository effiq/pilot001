# Pilot 001 — Final Verdict

**Verdict: PASS** — both halves of the pre-registered protocol, zero post-hoc changes.

**Claim.** On the declared workload (long-context inference, 4K–16K prompt tokens, three request forms, dynamic per-request output lengths), **FP8 dynamic quantization delivers 1.419× the end-to-end throughput of the BF16 default configuration** on an NVIDIA L40S serving Qwen2.5-14B-Instruct under vLLM — 95% bootstrap CI **[1.387×, 1.442×]**, pre-registered pass threshold 1.20× on the lower bound — **with no measurable quality loss** under a blind external judge (pre-registered tolerance: no axis may degrade by more than 0.1 on a 10-point scale; observed deltas were +0.05 to +0.21).

Everything below is reproducible from the archived raw logs. See [REPRODUCE.md](REPRODUCE.md).

---

## 1. Scope — what this verdict does and does not say

| In scope (declared before measurement) | Out of scope (no claim made) |
|---|---|
| GPU: single NVIDIA L40S 48GB, locked | Other GPUs (H100, consumer cards, …) |
| Model: Qwen2.5-14B-Instruct, revision `cf98f3b3bbb457ad9e2bb7baf9a0125b6b88caa8` | Other models |
| Engine: vLLM 0.31.0, torch 2.13.0+cu130, driver 580.159.03 | Other engines/versions |
| Workload: declared synthetic generator — 3 forms (doc_qa / code_completion / summarization), tiers 4096/8192/16384 prompt tokens, per-request max_tokens ~ U{200..800}, temperature 0, prefix caching OFF | Real customer traces (planned: Pilot 002) |
| Technique: FP8 dynamic quantization (vLLM built-in `quantization="fp8"`) | INT8, static quantization, speculative decoding (see §5) |
| Metric: (prompt+output tokens)/wall-second, per request | Latency percentiles, concurrency |

This verdict is a statement about **this workload on this hardware with this technique** — which is exactly the point of the Pilot series: acceleration claims should be measured, not assumed.

## 2. Governance — how this was kept honest

- **Protocol Lock v1.0** was frozen and published **before any measurement** (commit `3faaaa7`), including the success criteria, the workload generator, the statistical method, and the budget/window stop-loss rules.
- **Two amendments**, both signed and published **before any formal measurement data existed** (anchor commit `d0eabf3`):
  - *Amendment-01*: Arm B redefined from "FP8/INT8 + speculative decoding" to **FP8 dynamic quantization only**, after reconnaissance killed both speculative options (§5).
  - *Amendment-02*: request-level interleaving replaced by **block-crossover** (a 48GB card cannot hold both engines resident: 28GB BF16 + 14.3GB FP8 + KV > 46GB). Odd runs measure A first, even runs B first; pairing by request_id; statistical unit unchanged.
- **Anti-p-hacking**: the formal stage prints descriptive means only. The confidence interval stayed sealed inside an independent verdict script until all 6 COMPLETE markers existed.
- **Deterministic statistics**: bootstrap seed fixed at 20261006, 100,000 resamples. Same logs + same seeds → byte-identical verdict.
- **External trust domain**: the quality gate was scored by a third-party model via API (DeepSeek-V3-0324), blinded to arm identity by a seeded coin flip (seed 20261007). Raw judge responses are archived row by row. Qwen-family judges were excluded by design — a Qwen judge scoring Qwen outputs is a family conflict of interest.
- **Audit trail**: every artifact is hash-pinned (§6) and every stage script has a `--verify` entry that recomputes its outputs from the raw logs alone.

## 4. Quality half — PASS

Frozen evaluation set: 150 prompts (3 forms × 50; tier split 17/17/16), fixed seed 20261003, generated by the declared L2 generator. Both arms answered all 150 at temperature 0. Judge: `deepseek/deepseek-chat-v3-0324`, temperature 0, blind to arm labels. Three axes, integers 0–10.

| Axis | A (BF16) | B (FP8) | Δ = B−A | Tolerance |
|---|---|---|---|---|
| correctness | 6.487 | 6.700 | **+0.213** | ≥ −0.1 ✅ |
| instruction_following | 6.087 | 6.267 | **+0.180** | ≥ −0.1 ✅ |
| clarity | 5.820 | 5.873 | **+0.053** | ≥ −0.1 ✅ |
| **overall (pooled)** | | | **+0.149** | ≥ −0.1 ✅ |

Honest reading: the all-positive deltas are within judge noise — the descriptive bootstrap CI of the overall delta is [−0.144, +0.451], crossing zero. The correct statement is **"no measurable quality degradation"**, not "FP8 is better". Per-form descriptive deltas: doc_qa −0.387, code_completion +0.973, summarization −0.140. All 150 output pairs diverged textually (0/150 identical) while being judged equivalent — quantize-and-measure beats quantize-and-hope.

## 5. Two techniques were killed by evidence *before* the formal measurement

Publishing dead ends is part of the deal:

- **ngram speculative decoding — killed by measurement.** Offline simulation over archived (prompt, output) token streams (max_n=4, k_spec=5): acceptance **0.134** (4K 0.145 / 8K 0.154 / 16K 0.105) against the pre-registered 0.50 checkpoint. On this workload, ngram speculation would have been dead weight.
- **EAGLE speculative decoding — killed by ecosystem reality.** No official EAGLE/EAGLE-3 head exists for Qwen2.5-14B. The community head (`Zjcxy-SmartAI/Eagle-Qwen2.5-14B-Instruct`, listed in the official EAGLE weight table) uses architecture `Qwen2ForCausalLMEagle`, which vLLM's speculative registry does not support (SGLang-only). Within the locked boundary (no custom kernels, vLLM built-ins only), EAGLE was not deployable.

Both are documented in the public protocol amendments with evidence hashes.

## 7. Operational incidents, disclosed

- One formal run appeared dead mid-flight; in fact the web terminal's websocket had detached while the process completed in the background (terminal disconnect ≠ process death). No data lost; the retry logic correctly never fired.
- The quality gate process did die once mid-run (host hiccup; cause not captured). The resume design absorbed it: re-running the same command continued from the last archived row with zero rework beyond one engine load.

Both are recorded in the project archive. The measurement system is designed so that *interruptions cannot silently change results*: partial data never carries a COMPLETE marker, and the verdict scripts refuse incomplete inputs.
